# ReMgu

[English](README.md) | **Русский**

Управление жизненным циклом ML-экспериментов для воспроизводимых исследований.

ReMgu связывает исследовательскую гипотезу с конкретным запуском, его метриками и диагностическими примерами, а затем — с выводом и следующим шагом. История хранится в обычных файлах внутри `.research/`: её можно читать, версионировать и проверять без отдельного сервера трекинга.

> **Текущие возможности:** жизненный цикл запусков, параметры, метрики, диагностические примеры, read-only проверка согласованности, контролируемые графовые симуляции, автономные HTML-отчёты и необязательный локальный live-дашборд. База знаний и агентные сценарии не реализованы. Snapshot, ZIP-архивы, Markdown-отчёты и статические сайты доступны через `research update`, `research archive`, `research export markdown` и `research export site`.

## Исследовательский цикл

```text
вопрос / наблюдение
        ↓
  гипотеза + мотивация
        ↓
      run-001
        ├── params.yaml
        ├── metrics.csv
        └── samples.jsonl
        ↓
исполнение: completed / failed / aborted
        ↓
    вывод + следующий шаг
        ↓
   следующая гипотеза
```

**Run** — конкретное исполнение эксперимента. Гипотеза и мотивация объясняют, зачем оно проводится; метаданные исполнения фиксируют, что произошло; review — что удалось узнать и что делать дальше.

## Установка

ReMgu требует Python 3.10 или новее.

### Вариант 1: Использовать ReMgu в коде проекта

Если вы хотите импортировать ReMgu в своём коде (`from remgu import Experiment`),
установите пакет в окружение проекта:

```bash
pip install remgu
```

После этого команда `research` будет работать, пока вы находитесь в этом окружении:

```bash
research --help
```

### Вариант 2: Использовать команду `research` во всей системе

Если ReMgu нужен только как команда `research` (без импорта в коде),
установите его через [pipx](https://pipx.pypa.io):

```bash
pipx install remgu
```

Pipx создаёт отдельное окружение для `remgu` и добавляет команду `research` в `PATH`.
Команда будет доступна из любого каталога, без активации какого-либо окружения.

```bash
research --help
```

Обновление: `pipx upgrade remgu`.

## Быстрый старт

Создайте запуск перед обучением:

```bash
research new \
  --hypothesis "Увеличение hidden_dim до 512 улучшит NDCG@20" \
  --motivation-type previous_run \
  --reference run-001
```

Команда выведет идентификатор запуска. По умолчанию данные создаются в `.research/` текущего каталога; другой путь задаётся через `--base-path`. `run-001` здесь — пример: укажите реально существующий запуск либо используйте `--motivation-type new` без `--reference`.

В коде обучения:

```python
from remgu import Experiment

experiment = Experiment("graph-mamba")
with experiment.run() as run:
    run.log_params({"hidden_dim": 512, "learning_rate": 1e-3})

    # Здесь должен быть ваш код обучения и оценки.
    run.log_metric("ndcg_at_20", 0.428, step=1)
    run.collect({"example_id": "user-104", "score": 0.12, "reason": "large_regression"})
```

Вызов `experiment.run()` без аргументов продолжает активный запуск, созданный CLI. При нормальном выходе из `with` всё ещё выполняющийся запуск получает статус `completed`; необработанное исключение переводит его в `failed` и сохраняет тип и сообщение ошибки.

После проверки результата зафиксируйте вывод:

```bash
research finish run-001 \
  --conclusion "NDCG@20 вырос с 0.401 до 0.428 на фиксированной validation-выборке" \
  --next-step "Повторить с тремя random seed"
```

Используйте фактический ID из вывода `research new`; `run-001` — иллюстрация. Подробные сценарии: [CLI](docs/ru/cli.md) · [Python API](docs/ru/python-api.md).


## Интерфейсы

### Командная строка

```bash
research --help
research new --help
research status
research previous --limit 10
research resume run-001
research finish run-001 --conclusion "..." --next-step "..."
research check
research update
research archive
research export markdown
research export site
```

CLI использует `.research/` по умолчанию. Чтобы выбрать другой каталог, перед подкомандой укажите `--base-path /path/to/research-data`.

### Python API

```python
from remgu import Experiment, Motivation, Run, ExampleProvider, TopKSelector
from remgu import SimulationExperiment, SimulationConfig, RemoveEdgeOperator
```

- `Experiment` открывает активный запуск или программно создаёт новый.
- `Run` управляет состоянием исполнения и записывает параметры, метрики и диагностические записи.
- `Motivation` описывает, почему проверяется гипотеза.
- `TopKSelector` выбирает лучшие или худшие по заданной оценке диагностические записи, сохраняя ограниченный объём данных в памяти.
- `ExampleSelector` объединяет несколько критериев отбора и отмечает, почему выбран каждый пример.
- `ExampleProvider` задаёт интерфейс для получения исходного объекта и его текстового описания по ID.
- `SimulationExperiment` запускает контролируемый синтетический эксперимент; `SimulationConfig` фиксирует параметры и seed, а графовые операторы задают явные вмешательства.

Подробности и полные примеры — в [руководстве по API](docs/ru/python-api.md).

## Принципы

- **Контекст исследования хранится вместе с запуском.** Run содержит гипотезу и мотивацию, а не только набор метрик.
- **Обычный training script остаётся обычным.** ReMgu оборачивает существующий код, а не требует перехода на новый фреймворк обучения.
- **Источник истины — файлы.** YAML, CSV и JSONL можно читать, проверять и версионировать.
- **Исполнение и научный разбор разделены.** Успешный процесс ещё не означает, что результат осмыслен и проверен.
- **Исследовательский анализ не изменяет данные.** `research check`, `research update`, `research archive`, `research export markdown` и `research export site` не переписывают source of truth в `.research`.


## Симулятор, отчёты и дашборд

Эти инструменты нужны, чтобы проверить исследовательскую гипотезу, сохранить результат, изучить примеры или наблюдать за обучением в браузере. Выберите сценарий под свою задачу:

- **Провести воспроизводимый эксперимент на графе:** `research simulation run --seed 7 --nodes-per-community 8 --output result.json`
- **Открыть отчёт:** `research simulation report result.json --output report.html` — получится автономный HTML-файл.
- **Посмотреть сохранённый результат:** `research simulation dashboard result.json --port 8765`, затем откройте локальный адрес из вывода команды. Эта команда показывает данные из `result.json`, но не подключается к работающему обучению.
- **Наблюдать за обучением в реальном времени:** используйте `DashboardServer` с `with dashboard.run():` или декоратор `@dashboard.track()`. Сервер и мониторинг ресурсов запускаются и останавливаются автоматически. Чтобы видеть loss и accuracy по эпохам, передавайте функцию, возвращающую текущие метрики, либо вызывайте `dashboard.log_metrics(loss=..., accuracy=...)` после эпохи.

На дашборде можно увидеть историю метрик, доступные измерения CPU/RAM/GPU, отобранные примеры, граф и схему модели, а также сообщения обучения. Ползунок появляется только для параметра, который код эксперимента заранее разрешил менять во время обучения.

```python
from remgu import DashboardServer

dashboard = DashboardServer()

@dashboard.track()
def train():
    for epoch in range(num_epochs):
        train_one_epoch()
        dashboard.log_metrics(loss=loss, accuracy=validation_accuracy)

train()  # откроет дашборд на время обучения и закроет его после завершения
```

Для мониторинга CPU/RAM/GPU установите дополнительные зависимости: `pip install "remgu[monitor]"`. Если измерение недоступно на данной машине, оно будет показано как недоступное, а не как ноль. По умолчанию дашборд доступен только локально. Полные примеры и пояснения приведены в [руководстве по симуляции и визуализации](docs/ru/simulation.md).

## Статус разработки

ReMgu развивается как исследовательский инструмент. Текущая реализация намеренно небольшая и основана на файлах. Пакет симуляции без обязательных ML-зависимостей поддерживает базовый сценарий графовой зависимости, вмешательства в граф, воспроизводимые преобразования и необязательные диагностические контракты. Доступны браузерная визуализация, автономные HTML-отчёты, live-дашборд, отбор примеров, опциональный мониторинг ресурсов и схемы моделей для поддерживаемых ML-фреймворков. DOT-рендерер намеренно поддерживает безопасное подмножество Graphviz.
