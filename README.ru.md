# ReMgu

[English](README.md) | **Русский**

Управление жизненным циклом ML-экспериментов для воспроизводимых исследований.

ReMgu связывает исследовательскую гипотезу с конкретным запуском, его метриками и диагностическими примерами, а затем — с выводом и следующим шагом. История хранится в обычных файлах внутри `.research/`: её можно читать, версионировать и проверять без отдельного сервера трекинга.

> **Текущие возможности:** жизненный цикл запусков, параметры, метрики, диагностические примеры и read-only проверка согласованности. База знаний, агентные сценарии, генерация отчётов/сайта и команда `research update` в этой версии не реализованы.

## Исследовательский цикл

```text
вопрос / наблюдение
        ↓
  гипотеза + мотивация
        ↓
      run-001
        ├── params.yaml
        ├── metrics.csv
        └── samples.jsonl
        ↓
исполнение: completed / failed / aborted
        ↓
    вывод + следующий шаг
        ↓
   следующая гипотеза
```

**Run** — конкретное исполнение эксперимента. Гипотеза и мотивация объясняют, зачем оно проводится; метаданные исполнения фиксируют, что произошло; review — что удалось узнать и что делать дальше.

## Установка

ReMgu требует Python 3.10 или новее.

### Вариант 1: Использовать ReMgu в коде проекта

Если вы хотите импортировать ReMgu в своём коде (`from remgu import Experiment`),
установите пакет в окружение проекта:

```bash
pip install remgu
```

После этого команда `research` будет работать, пока вы находитесь в этом окружении:

```bash
research --help
```

### Вариант 2: Использовать команду `research` во всей системе

Если ReMgu нужен только как команда `research` (без импорта в коде),
установите его через [pipx](https://pipx.pypa.io):

```bash
pipx install remgu
```

Pipx создаёт отдельное окружение для `remgu` и добавляет команду `research` в `PATH`.
Команда будет доступна из любого каталога, без активации какого-либо окружения.

```bash
research --help
```

Обновление: `pipx upgrade remgu`.

## Быстрый старт

Создайте запуск перед обучением:

```bash
research new \
  --hypothesis "Увеличение hidden_dim до 512 улучшит NDCG@20" \
  --motivation-type previous_run \
  --reference run-001
```

Команда выведет идентификатор запуска. По умолчанию данные создаются в `.research/` текущего каталога; другой путь задаётся через `--base-path`. `run-001` здесь — пример: укажите реально существующий запуск либо используйте `--motivation-type new` без `--reference`.

В коде обучения:

```python
from remgu import Experiment

experiment = Experiment("graph-mamba")
with experiment.run() as run:
    run.log_params({"hidden_dim": 512, "learning_rate": 1e-3})

    # Здесь должен быть ваш код обучения и оценки.
    run.log_metric("ndcg_at_20", 0.428, step=1)
    run.collect({"example_id": "user-104", "score": 0.12, "reason": "large_regression"})
```

Вызов `experiment.run()` без аргументов продолжает активный запуск, созданный CLI. При нормальном выходе из `with` всё ещё выполняющийся запуск получает статус `completed`; необработанное исключение переводит его в `failed` и сохраняет тип и сообщение ошибки.

После проверки результата зафиксируйте вывод:

```bash
research finish run-001 \
  --conclusion "NDCG@20 вырос с 0.401 до 0.428 на фиксированной validation-выборке" \
  --next-step "Повторить с тремя random seed"
```

Используйте фактический ID из вывода `research new`; `run-001` — иллюстрация. Подробные сценарии: [CLI](docs/ru/cli.md) · [Python API](docs/ru/python-api.md).


## Интерфейсы

### Командная строка

```bash
research --help
research new --help
research status
research previous --limit 10
research resume run-001
research finish run-001 --conclusion "..." --next-step "..."
research check
```

CLI использует `.research/` по умолчанию. Чтобы выбрать другой каталог, перед подкомандой укажите `--base-path /path/to/research-data`.

### Python API

```python
from remgu import Experiment, Motivation, Run, ExampleProvider, TopKSelector
```

- `Experiment` открывает активный запуск или программно создаёт новый.
- `Run` управляет состоянием исполнения и записывает параметры, метрики и диагностические записи.
- `Motivation` описывает, почему проверяется гипотеза.
- `TopKSelector` выбирает лучшие или худшие по заданной оценке диагностические записи, сохраняя ограниченный объём данных в памяти.
- `ExampleSelector` объединяет несколько критериев отбора и отмечает, почему выбран каждый пример.
- `ExampleProvider` задаёт интерфейс для получения исходного объекта и его текстового описания по ID.

Подробности и полные примеры — в [руководстве по API](docs/ru/python-api.md).

## Принципы

- **Контекст исследования хранится вместе с запуском.** Run содержит гипотезу и мотивацию, а не только набор метрик.
- **Обычный training script остаётся обычным.** ReMgu оборачивает существующий код, а не требует перехода на новый фреймворк обучения.
- **Источник истины — файлы.** YAML, CSV и JSONL можно читать, проверять и версионировать.
- **Исполнение и научный разбор разделены.** Успешный процесс ещё не означает, что результат осмыслен и проверен.
- **Проверки ничего не исправляют автоматически.** `research check` только сообщает о проблемах и не переписывает данные запусков.

## Статус разработки

ReMgu развивается как исследовательский инструмент. Текущая реализация намеренно небольшая и основана на файлах. Документация описывает код в этом репозитории; управление базой знаний, публикация и агенты пока не входят в реализованный функционал.
