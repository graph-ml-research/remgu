# Формат данных на диске

[English](../en/data-format.md) | [Русский](../../README.ru.md)

По умолчанию ReMgu записывает данные в `.research/` относительно текущего рабочего каталога:

```text
.research/
├── active                  # ID активного запуска; отсутствует, если активного запуска нет
└── runs/
    ├── run-001/
    │   ├── run.yaml        # гипотеза, мотивация, исполнение, разбор
    │   ├── params.yaml     # снимок фактической конфигурации (создаётся при первом log_params)
    │   ├── metrics.csv     # добавляемые записи метрик (создаётся при первой метрике)
    │   └── samples.jsonl   # компактные диагностические записи (создаётся при первом collect)
    └── run-002/
        └── run.yaml
```

Файлы артефактов создаются по мере необходимости. В каждом запуске необязательно присутствуют все три артефакта.

## `run.yaml`

```yaml
run_id: run-003
research:
  hypothesis: "Increasing hidden_dim to 512 improves NDCG@20."
  motivation:
    type: previous_run
    reference: run-002
execution:
  status: completed
  started_at: "2026-09-19T00:00:00Z"
  finished_at: "2026-09-19T01:00:00Z"
  error: null
review:
  status: needs_review
  conclusion: null
  next_step: null
```

Это пример схемы, а не реальные данные: значения и время должны описывать конкретный запуск. Статус исполнения — `running`, `completed`, `failed` или `aborted`. Статус разбора — `needs_review` или `reviewed`.

### Различие двух жизненных циклов

Исполнение отвечает на вопрос **что произошло при запуске кода?** Разбор отвечает на вопрос **какой вывод мы делаем и что нужно сделать дальше?** Завершённый запуск может оставаться в состоянии `needs_review`, пока исследователь не запишет вывод и следующий шаг.

## Артефакты

- `params.yaml`: словарь фактических параметров запуска. Повторные вызовы `log_params` объединяют ключи; новое значение заменяет прежнее для того же ключа.
- `metrics.csv`: добавляемые строки со столбцами `step`, `metric_name`, `metric_value`. Одно имя метрики может встречаться на разных шагах.
- `samples.jsonl`: по одному компактному JSON-объекту на строку, обычно с `example_id`. Предпочтительнее ссылка на исходный пример, а не копия больших записей или датасета.

## Указатель активного запуска и ID

Файл `active` содержит ID, например `run-003`. Новый ID получается увеличением максимального числового суффикса в каталоге runs и форматируется минимум тремя цифрами. Указатель удаляется при завершении, ошибке или отмене запуска.

## Контроль версий

Это обычные текстовые файлы, которые можно коммитить вместе с кодом эксперимента. Отдельно решите, допустимо ли помещать в Git большие или чувствительные диагностические поля: ReMgu автоматически не обезличивает и не фильтрует собранные записи. Не сохраняйте учётные данные, персональные данные или полные закрытые датасеты без явной политики работы с данными.
